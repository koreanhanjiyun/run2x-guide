## 2. 시안 만들기 · 검사 · 공개

```bash

# 검사 (Playwright, 콘솔 오류 없어야 함)

# (node 가 playwright 를 못 찾으면 NODE_PATH=$(npm root -g) 를 앞에 붙임)

# 공개 시안 갱신: main 작업 트리에 draft/ 만 넣어 커밋 · 푸시
git fetch origin main && git worktree add --detach ../mainwt origin/main
python3 tools/draft/publish.py ../mainwt
cd ../mainwt && git add draft && git commit -m "시안 갱신: draft/ (redesign-v1 <커밋>)" && git push origin HEAD:main
```

- `tools/draft/demo-mock.js`: 가짜 저장소 + 역할 전환 막대(비로그인 · 팀원 · 팀장 · 파트장 · 회장) + 도구 1 예시 데이터(어셈블리 18개, 드라이버 3명). 예시 데이터를 바꾸면 `demo-mock.js` 의 키(`__run2xdemoNN`, `run2x.mass.vN`)와 `qa/h2.js` 의 KEY 를 같이 올려야 이미 본 브라우저에도 새 데이터가 들어감.
- `publish.py` 는 브라우저 저장 키 앞에 `run2x-draft:` 를 붙여 실제 사이트 저장값과 섞이지 않게 하고, 사진은 사이트의 `img/` 를, 3D 라이브러리는 `draft/vendor/three/` 를 쓴다.
- `main` 푸시는 작업 환경의 권한 검사에서 막힐 수 있다. 그때는 관리자에게 허락을 받는다.

## 3. 관리자와 정한 작업 규칙

- 명확한 실행 지시("ㄱㄱ", "진행", "반영", "가자", "해줘" 등) 없이는 파일을 고치지 않고 논의만 한다. 답변은 한국어 존댓말, 답부터, 선택지는 표 + (권장).
- 지시받아 끝낸 작업은 묻지 않고 `redesign-v1` 에 커밋 · 푸시하고, 공개 시안(`draft/`)도 같이 갱신한다. 그 밖의 `main` 반영(배포 · 버전 올림)은 지시가 있을 때만.
- 사이트 본문에는 출처를 쓰지 않고 참고 탭에 모은다. "추측" · "확인 필요" 같은 말은 사이트 글에 쓰지 않는다. 디버깅 모드는 공개 변경 이력에 쓰지 않는다.
- PC Chrome 1440 px 이상만 지원(모바일 미지원). 애니메이션 · 부드러운 이동은 OS '움직임 줄이기' 설정과 상관없이 항상 동작.
- 비밀번호 입력 · 대신 로그인 금지. 서비스 계정 키는 저장소 · 대화에 넣지 않는다.

## 4. 도구 1 (질량 · 무게중심) 결정 사항

- 부품 질량 표: 어셈블리 하나 = 문서 하나 `teams/<팀>/mass/<id>` (docs/STORE-PLAN.md 2절). 좌표는 사이트 차량 좌표계(ISO 8855 방향, 2026-11-04 결정): 원점 = 뒤 차축 중심 · 차량 중심면 · 지면, x = 앞으로 +, y = 왼쪽 +, z = 위 + [mm]. 설계 탭 좌표계 그림 · 도구 탭 [좌표계]와 같음. 드라이버 그림 · 차 윤곽은 안에서 '앞 차축에서 뒤로' 좌표로 그리므로 그릴 때만 x_그림 = L − x.
- 카드 배치: 4열, 줄마다 왼쪽부터 빈칸 없이. 카드 위에 놓으면 그 앞에 끼우고, 줄이 넘치면 마지막 카드가 바로 아래 새 줄로. 줄 끝 빈칸 = 그 줄 끝, 줄 사이 = 새 줄. 드라이버 카드는 첫 줄 첫 칸 고정(첫 줄 3장).
- 걸침(½): 항목마다 체크(기본 해제). 체크한 항목 질량의 절반은 반대쪽으로 — 현가하 카드면 현가상, 현가상 카드면 가장 가까운(3차원) 현가하 카드의 앞 · 뒤(없으면 휠베이스 절반 기준). 저장은 항목의 `half: true`.
- 드라이버 카드 항목(몸무게 · 헬멧 · 드라이버 복 · 안전벨트)은 드라이버 모델 값과 같은 값. 드라이버 실측 CG 기능은 관리자 지시로 뺐다(2026-11-04).
- 드라이버 모델: de Leva 1996 표 4 (머리 · 목 VERT–CERV, 몸통 CERV–MIDH 무게중심 51.38 % / 49.64 %, 정강이 KJC–LMAL 44.59 % / 44.16 %, 남 / 여). 발은 발목 높이 0.039 H · 발 길이 0.152 H 비율(Winter 2009 그림 4.1, Drillis & Contini), 뒤꿈치 ~ 발목 0.22 × 발 길이는 근사.
- 헬멧 색: 1st 보라 `#6A4294` · 2nd 파랑 `#1d5f9a` · 3rd 주황 `#c2410c`.
- 차 형상(그림 바탕, `js/app/car-shape.js`): 작업창 위 막대 [차 형상](도구 정의 `shape: true`). 질량 분포(옆 · 위) · 드라이버 모델 그림에만 쓰고 대시보드 '그림으로 보기'는 기본 차 그림. 옆면 3단계(범위 자르기 → 앞 바퀴 중심 점 → 뒤), 윗면 4단계(자르기 → 앞 차축 중심선 → 뒤 차축 중심선 → 차량 중심선, 차 길이가 가로인 그림 가정). 휠 확대 · 휠 버튼/Ctrl 끌기 이동 · 전체 보기. 옆면은 앞이 오른쪽이면 좌우 뒤집기, 윗면은 돌리기만. DXF 는 원 중심에 붙음. 저장 뒤 [저장된 그림 다시 편집](저장본 범위 안에서 다시 자르기 · 찍기, 처음 파일은 보관 안 함). 읽을 수 없는 확장자는 한 문구로 안내. `shape/{side|top}` 시즌별(약 850 kB), 계산에는 쓰지 않음.
- 작업창 [? 이 탭 사용법] (사이트 사용법 칩과 같은 모양): `WB_TOOLS[번호].tour` 에 단계를 두면 생김. 표 탭이 바뀌는 단계는 `click`, 작업창 안쪽 스크롤은 `inner` 로 부드럽게.

## 4-2. 도구 2 (랩타임) 결정 사항 (2026-11-05, 관리자 지시로 권장안 그대로)

- 모델: 점질량 준정적(QSS) + 앞뒤 하중 이동(종가속 · 항력 높이 · 다운포스 앞뒤 몫) + 좌우 하중 이동(앞 몫 = 대시보드 `lltd`) + 타이어 μ 하중 감도(`mu_s`, μ = μ0 − μs × 하중 kN, 축 힘 = Σ μ·Fz) + 뒤축 구동(모터 1개) + 축 단위 마찰원. 횡력은 무게 배분대로 앞뒤에 나눔. 제동은 이상 배분 가정(제동 장치 한계는 도구 3). 롤 · 회생 제동 · 디퍼렌셜은 넣지 않음.
  - 하중 감도가 0이면 좌우 하중 이동은 결과를 바꾸지 않음. 도구 7 전에도 대시보드 `lltd` 값을 그대로 씀(관리자 결정).
- 예전 계산기 오류 고침: 회전부 등가 질량 J ÷ r², 구름 저항 = 계수 × (무게 + 다운포스).
- 코스(작업창 위 [코스]): 내 코스 · 오토크로스 · 내구레이스 · 가속 · 스키드패드. 공식 4개는 고칠 수 없음.
  - 내구 = FSK 2026 공식 코스(`js/data/fsk2026-course.js`, 대회 공개 JSON에서 중심선 · 폭 · 콘, 곡률은 σ 3 m 로 다듬음) 850.76 m × 26랩, 드라이버당 13랩(대회 공식), 각 드라이버 정지 출발, 교체 시간 제외. 파란 콘 = 오른쪽. 볼 랩 1 ~ 26 · 전체. 랩별 기록 표(누르면 그 랩).
  - 오토크로스 = 내구 코스를 거꾸로 한 바퀴, 정지 출발. 가속 = 75 m. 스키드패드 = 8자(반경 9.125 m, 진입 → 오른쪽 2 → 왼쪽 2 → 탈출, 기록은 정상 선회).
  - 내 코스 = 아래 '코스 탭' 항목(표 직접 고치기 · [코스 입력하기]).
  - 지도: 출발선 초록 · 결승선 빨강(닫힌 코스는 결승선을 살짝 앞에), 주행 방향 삼각형, 커서 점 반지름 4, 공식 코스는 콘.
- 모터([맵 편집] 모터 토크 곡선): 기본 = EMRAX 228 데이터시트에서 뽑은 곡선(`js/data/emrax228.js`, 원자료 · 추출 스크립트 `docs/data/emrax228/`; 예전 3,500 rpm 엑셀 표는 쓰지 않음 — 관리자 결정). 표 2열 = 최대 토크, 3열 = 연속 토크(디레이팅 하한). 회전수 축을 (단자 전압 ÷ 표 기준 전압 710 V) ÷ 유도 전압 비(MV ÷ HV = 0.04793 ÷ 0.07348)로 늘이고 줄임.
- 모터 열 · 디레이팅(2026-11-05, 관리자 결정): 1점 모델 C·dT/dt = 모터 손실(축 출력 × (1 ÷ 모터 효율 − 1), 인버터 손실 제외) − (T − 냉각수) ÷ R. 토크 한계 = 최대 − 계수 × (T − 시작 온도), 연속 곡선 아래로는 안 감. 계수 0 = 항상 최대(기본값). 열용량 6000 J/K · 열저항 0.02 K/W · 냉각수 40 °C 는 예시값(실제 값 모름). 내구는 교체 뒤에도 온도 이어짐. 랩마다 두 번 계산(온도 반영).
- 타이어 하중 감도 맵([맵 편집]): 바퀴 하중 N → μ 표(직선 보간). 있으면 왼쪽 μ · 감도 칸을 막고 표를 씀.
- 축전지 기본값(37차부터): 삼성 SDI 40T 70s7p (셀 4.2 / 3.6 / 2.5 V, 4.0 Ah), 팩 저항 120 mΩ, 전류 한계 245 A, 충전 42 A (예전 P45B 72S6P · 180 mΩ · 270 A). 개방 전압은 SOC에 선형(근사), 단자 전압 = 개방 − 전류 × 저항. 단자 출력 ≤ min(규정 상한, 전류 한계).
- 내구 에너지 제한: `e_target`(0 = 팩 전체). 소비(개방 전압 × 전류)가 넘으면 단자 출력 상한을 같은 비율로 낮춰 맞춤(할선법).
- 결과(2026-11-05 2차, 관리자 결정): 점수 · 목표 차이 · 내 코스는 결과에서 뺌. [내 감속비 | 최적 감속비]는 [시뮬레이션] 위 줄 왼쪽, 두 모드를 한 번에 계산해 두고 전환은 바꿔 끼우기만(`R.modes`).
  - 1행 3열: 감속비(제안 · 가속 · 스키드패드 — · 오토크로스 · 내구, 가장 빠른 감속비와 그때 기록, 같은 글자 크기) · 종목 기록(같은 종목이 같은 높이, ± = 가장 빠른 기록 대비 초록 −0.000s · 빨강 +0.000s) · 차량 한계. 60초 넘는 기록은 25m 17.2s.
  - 스키드패드 기록 = 오른쪽 한 바퀴 + 왼쪽 한 바퀴(목표도 합). 지금 모델은 좌우 대칭이라 같은 값(좌우 무게 배분은 나중). 필요 C_L·A 는 ±15 m² 안에서 음수까지.
  - 2행 3열 고른 코스 · 축전지 · 모터(모터 온도 포함) · 에너지: 고른 코스 · 볼 랩. 감속비 = 내 감속비 모드면 입력, 최적 모드면 그 코스에서 가장 빠른 값(스키드패드는 최적 감속비), 표시만.
  - 그래프 · 지도도 3행과 같은 감속비. 대시보드 '차량 목표'는 대시보드 감속비 기준 예상 대 목표 기록 그대로.
- 감속비: 2.5 ~ 7.0 을 0.5 간격 → 가장 좋은 곳 ± 0.4 를 0.1 간격(줄여 셈). 제안 J = Σ 배점 × (입력 감속비 기록 − 그 감속비 기록) ÷ 입력 감속비 기록 (가속 100 · 오토크로스 200 · 내구 350, 스키드패드 제외). 입력 훑기 중에는 건너뜀(`_sweep`).
- 3차(2026-11-06, 관리자 결정): 탭 줄에는 [시뮬레이션 | 맵 편집]만, 고르기 줄은 탭 안 첫 줄. 맵 편집은 왼쪽 [메뉴 줄 + 표 상자] · 오른쪽 [안내 줄 + 그림 상자] 같은 높이(360 px). 공식 코스 표는 회색(보기만). 표 아래 [+ 줄 · + 행 · + 열]은 늘 보임(빈 표면 머리줄부터 만듦). 메뉴 이름 '예시 코스로 · 예시 곡선으로 · 예시 효율 맵으로', 모든 표에 [비우기](내 코스를 비우면 계산 안 함).
