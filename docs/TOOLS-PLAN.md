# 도구 탭 계획 (작업 기록)

마지막 갱신: 2026-11-01 · 상태: **결정 1~7 · 화면 구성 확정, 도구 탭 시안 진행 중 (실제 사이트 반영 전)**

이 문서는 도구 탭 대규모 작업의 목적, 확정된 결정, 아직 정할 것, 만들 순서와 할 일을 모아 둔 기록입니다.
도구 탭과 관계없는 작업(색 정리 시안, STEP 렌더 도구 준비 등)은 여기에 적지 않습니다.

---

## 1. 목적

예전 Run2X는 도구가 .m 파일과 엑셀로 흩어져 있었습니다. 이 도구들은 입력을 코드 안에서 직접 고쳐야 했고, 결과는 figure로만 나왔으며, 검증 기록도 없었습니다.
사이트 도구 탭은 다음을 목표로 합니다.

- 계산기를 한곳에 모으고 설계 단계 입출력으로 연결한다.
- 팀의 확정 설계값을 대시보드 한 곳에서 관리한다. 계산기는 그 값으로 입력을 채우고, 계산 결과를 다시 대시보드에 반영할 수 있다.
- 도구마다 검증표(해석해, 극한 사례, 독립 구현과의 교차 비교)를 둔다.

### 예전 자료의 위치 (참고만, 기반 아님)

- 예전 파일: `ackerman_ratio_auto_calculator_Ver121_develop.m`, `Optimum_Gear_Ratio_Calculator_Ver221_develop.m`, `brake_proportioning_auto_calculator.m`, C.G calculator xlsx, Endurance Track / EMRAX / T-W curve xlsx, EMRAX 문서.
- 새 도구는 이 파일들을 기반으로 하지 않는다. 계산 모델은 문헌·표준과 수식 유도로 새로 세운다.
- 예전 .m 결과와는 "참고 비교"로만 나란히 놓는다. 차이가 나면 수식 유도로 어느 쪽이 맞는지 판정한다.
- 모터 데이터와 내구 트랙은 입력 예시로 쓸 수 있다. 쓸지는 도구를 만들 때 정한다.

### 예전 코드에서 발견한 오류 (따라가지 말 것)

| 파일·위치 | 내용 | 근거 |
|---|---|---|
| 기어비 .m 648행 | 가속도 분모가 `m + J/LR` | 회전 관성의 등가 질량은 J/r². J/r은 단위가 kg·m라 질량과 더할 수 없음 |
| 기어비 .m 355·632행 | 구름 저항이 다운포스×0.02뿐 | 무게 항 m·g·Crr이 빠짐 |
| 애커먼 .m 185~190행 | 애커먼 100%를 목표로 최적화. 첫 점 오차는 0으로 처리 | 사이트 카드는 부분 애커먼. 비율 지표는 작은 조향각에서 발산함 |
| 제동 .m | 목표 감속도 한 점에서만 이상 배분을 구함 | 범위가 좁음. 3번 도구로 흡수 |

## 2. 확정된 구조

### 2.1 도구 탭 (새 상단 탭)

- 예전에 정한 "새 상단 탭 없음, 참고 탭의 도구 모음"을 **대체한다**.
- 항목 안 [열기] 버튼과 검색으로 들어가는 길은 그대로 유지한다.
- 탭 위치: 상단 탭 **시작 · 설계 · 도구 · 참고 · 팀**. 도구는 설계 바로 오른쪽(설계 항목을 읽다가 옆 탭에서 계산). 연결도는 1.3.7부터 설계 탭 안의 보기라 따로 탭이 없다.
- 지원 환경: PC 크롬, 화면 너비 1440 px 이상(권장 1920×1080). **모바일은 지원하지 않는다.**
- 탭 구성 (위에서 아래로):
  1. **팀 대시보드 머리**: 작은 제목 "우리 팀 설계값", 큰 제목 "팀 대시보드", 한 줄 설명.
  2. **설계값**: 카드로 쪼개지 않고 한 덩어리에 분야별 열로 묶는다(질량·무게중심 / 치수 / 에어로 / 타이어·서스·조향 / 파워트레인). 열마다 굵은 윗선, 줄마다 이름 · 값 · 단위 · 상태 점(확정 · 검토 중 · 가정 · 계산값). 값을 눌러 바로 고친다. 계산값(예: 무게중심 위치, 회전수 한계 최고속)은 기울임으로 구분.
  3. **그림으로 보기**: 아래 2.5절.
  4. **파트별**: 밑줄 탭. 파트 그림은 그 계산 도구를 만들 때 하나씩 연다(아래 2.5절 시각화 범위).
  5. **도구 모음**: 시작 탭 연표처럼 줄 목록(번호 · 단계 · 이름 · 입력 → 출력 · 상태). 누르면 전체 화면 작업창.
- 디자인: 시작 탭처럼 카드 상자 없이 굵은 윗선 · 얇은 구분선 · 여백으로 나눈다. 길거나 격자이거나 펼쳐 보는 묶음만 판(흰 바탕, 1 px 옅은 테두리, 모서리 8 px)으로 감싼다.

### 2.2 계산기 사용 흐름

1. 계산기를 연다. 화면 전체를 쓰는 작업창으로 열리며, 항목 안에 펼치는 방식은 쓰지 않는다.
2. **[대시보드 값으로 채우기]** 를 누르거나 처음부터 직접 입력한다. 대시보드와는 독립적으로 동작한다.
3. 값을 자유롭게 고쳐 가며 여러 번 계산한다.
4. 마음에 드는 결과는 **[대시보드에 반영]** 하거나 직접 옮겨 적는다.

### 2.3 설계 탭과의 관계

- 우리 팀 값 편집은 설계 탭에 둘 필요가 없다. 도구 탭에 입력되면 설계 탭 항목에 자연스럽게 보이게 한다.

### 2.4 작업창 공통 사양 (이전 논의에서 확정)

- 기본 결과 그래프를 둔다. 여기에 INCA 방식의 신호 선택 그래프를 부가 기능으로 붙인다.
- 코드 보기·수정 기능을 둔다. 실행은 Web Worker 샌드박스에서 한다.
  - 고친 코드는 서버에 저장하지 않으며, 다시 열면 원래 코드로 돌아간다.
- 입력값은 이 브라우저에 기억한다(localStorage).
- 공유는 사이트 양식의 내보내기·가져오기(.json)와 대시보드로 한다. 행 단위 붙여넣기는 넣지 않는다.
- 그래프 라이브러리(uPlot, Chart.js 등)는 신호 선택 그래프용으로만 검토한다.
- 3D 화면(도구 4~7)은 three.js로 그린다. 외부 CDN이 아니라 저장소 `vendor/three/`에 넣어 쓴다(MathJax와 같은 방식).
- 그림은 REF4 STEP을 작업창에서 직접 렌더링하는 것이 기본이다. 지윤이 무료 뷰어 캡처를 보내 주면 그것을 쓴다.

### 2.5 대시보드 시각화 (그림으로 보기 · 파트별)

**역할 구분**: '그림으로 보기'는 지금 주행 조건 한 순간의 시각화, '파트별'은 전체 범위의 선도(그래프)에 지금 조건을 세로 점선으로 표시하는 자리.

**그림 배치**: 2×2 — 위 줄 측면도 · 윗면도, 아래 줄 앞에서 · 뒤에서(축별 정면도). 그 오른쪽 칸에 주행 조건과 결과 숫자를 세로로 둔다. 설명 문장은 네 그림 아래 전체 폭.

| 영역 | 내용 |
|---|---|
| 측면도 | REF4 CAD 투영 윤곽(카울·프레임·축전지·모터·날개 외곽선 하나·드라이버). 앞뒤 오버행은 REF4 그대로, 두 축 사이는 휠베이스 값으로 늘고 줆. 무게중심·CoP 기호(원 + 십자, 2·4사분면 칠함; CG는 빨강, CoP는 파랑), CG·CoP 높이 치수는 차 앞쪽 바깥에, 휠베이스 치수, 다운포스·항력 화살표(파랑), 종방향 관성력 화살표(빨강, 가속도 반대 방향 = 하중이 옮겨 가는 쪽), 앞뒤 축하중(바퀴 색 + 반력 화살표 + N · % · 정지 대비) |
| 윗면도 | 같은 차를 위에서 그림(앞날개는 노즈 아래). 바퀴 색(두 그림 같은 기준) + 바퀴별 하중 N · % · 정지 대비 변화, 선회 시 CG 경로와 관성력 화살표(빨강), 앞바퀴 조향각(저속 애커먼, 뒤축 중심 반경 R<sub>r</sub> = √(R² − b²)). 두 그림 아래 전체 폭에 정지 코너웨이트 · 크로스 웨이트 |
| 앞에서 · 뒤에서 | REF4 정면 투영 윤곽(카울·메인 롤후프·날개·드라이버). 그 축의 좌우 바퀴 하중(바퀴 색 + 반력 화살표 + N · % · 정지 대비), 트레드 치수, CG 높이, 횡방향 관성력 화살표, 그 축의 횡하중 이동 ΔF<sub>z</sub>. 도구 4 이후 롤센터·캠버·트레드 변화(휠 얼라이먼트)와 측면도 롤 축 점선, 도구 6 이후 롤 각(변위 과장 배율 표시) |
| 주행 조건 칸 | 차속(최대 = 모터 회전수 한계 최고속) · 직진/좌회전/우회전 · 코너 반경(60 m → 설계 최소 회전 반경, 곡률 기준 눈금) · 종가속(0 가운데, ±2 g) · 에어로 포함/제외, 예시 상황(정지 · 발진 가속 · 최대 제동 · 스키드패드 · 헤어핀 · 고속 직선). 결과: 횡가속도, 그립 사용률(한계 초과 표시), 다운포스 · 항력, 앞뒤 축하중 비율 |
| 계산 가정 | 정상 상태, 롤에 의한 CG 이동 무시, 타이어 하중 감도 무시. 횡하중 이동은 앞 롤강성 배분 값으로 앞뒤에 나눔(도구 6 전에는 가정값으로 표시) |

**시각화 범위**: 공통 그림(측면도 · 윗면도 · 에어로)은 대시보드에 바로 둔다. 파트별 패널은 해당 계산 도구를 만들 때 같은 계산 엔진으로 붙인다(계산을 두 벌 만들지 않음).

| 파트 탭 | 열리는 시점 |
|---|---|
| 에어로 (차속별 다운포스 · 항력, 축하중) | 지금 |
| 차량 목표, 파워트레인 | 도구 2 |
| 제동 | 도구 3 |
| 서스 기하 | 도구 4 |
| 조향 | 도구 5 |
| 스프링 · ARB | 도구 6 |

**켜고 끄는 항목**: 에어로 포함/제외는 지금 둔다(제외하면 CoP 기호·라벨·높이 치수를 숨김). 서스(히브 · 피치 · 롤 변위와 롤에 의한 CG 이동)는 도구 4·6을 만들 때 그 설계값(휠 레이트, 안티 %, 롤강성, 롤센터)과 함께 연다. 변위는 실제 크기(수 mm, 1~2°)로는 안 보이므로 '변위 과장 ×배율'을 밝히고 그린다(설계 탭 서스 4모드 그림과 같은 방식).

**계산 모델 선택 (확정 2026-11-01)**: 주행 조건 칸에 서로 독립인 선택 3개를 둔다. 그림 위 가정 표시는 선택에 따라 자동으로 바뀐다.

| 선택 | 바뀌는 것 | 필요한 값 | 여는 시점 |
|---|---|---|---|
| 에어로 포함 | 다운포스 · 항력 (제외하면 CoP 표시 숨김) | C<sub>L</sub>A, C<sub>D</sub>A, CoP | 지금 |
| 타이어 하중 감도 포함 | 바퀴마다 μ가 하중에 따라 줄어듦 → 롤강성 배분이 앞뒤 균형에 영향 | 기준 하중 μ, 하중 감도 계수 | 도구 2 |
| 서스 포함 | 히브 · 피치 · 롤 변위(변위 과장 ×배율 표시), 롤에 의한 CG 이동 | 휠 레이트, 롤강성, 롤센터, 안티 % | 도구 4·6 |

**언더 · 오버 표현 (확정 2026-11-01)**: 용어는 두 뜻을 구분한다. (A) 조향 특성 — 선형 범위에서 같은 반경에 필요한 조향각이 애커먼 각보다 커지면 언더, 작으면 오버(언더스티어 계수 K = W<sub>f</sub>/C<sub>αf</sub> − W<sub>r</sub>/C<sub>αr</sub>, 앞뒤 슬립각 차이로 생김. 앞뒤 슬립각이 같으면 중립이고 경로는 의도와 같음). (B) 한계 언더·오버 — 그립을 다 쓸 때 앞뒤 중 먼저 미끄러지는 축.

| 구분 | 계산 | 그림 |
|---|---|---|
| (A) 조향 특성 | δ = L/R + K·a<sub>y</sub> | 윗면도에 점선 '의도한 경로'(애커먼 조향각 그대로일 때)와 실선 '실제 경로'(CG), 바퀴별 슬립각 화살표. 경로 차이는 작으므로 '과장 ×배율' 표시 |
| (B) 한계 균형 | 축별 필요 횡력 ÷ Σ(하중 감도 μ × 바퀴 하중) | 결과 칸에 앞 · 뒤 그립 사용률 막대와 '앞이 먼저 한계(언더)' 문구, 윗면도에서 먼저 한계인 축 바퀴 테두리 강조, 100 % 초과 시 실제 경로가 바깥으로 밀리거나(언더) 뒤가 돌아가는(오버) 모습 |

그립 사용률이 낮을 때는 (A), 높을 때는 (B)를 앞세운다(경계값은 타이어 데이터로 정함). 타이어 값은 대시보드 '타이어' 묶음에 숫자 + 출처 + 상태로 둔다. TTC(Tire Test Consortium, 유료) 데이터가 있는 팀은 거기서 맞추고, 없는 팀은 문헌값을 '가정'으로 표시해 쓰거나 도구 8(주행 데이터, 스키드패드 등)에서 맞춘 값을 쓴다. 값이 '가정'이면 그림과 결과에도 '가정 타이어 값'을 표시한다.

**계산기 작업창 배치**: 상단 막대(도구 모음으로 · 이름 · 단계 · 검증표 · 코드 보기 · .json 내보내기·가져오기 · 대시보드에 반영 · 닫기), 왼쪽 입력(대시보드 값으로 채우기, 대시보드와 다른 값 색 표시), 오른쪽 결과 숫자(대시보드 값과 나란히) → 기본 결과 그래프 · 3D 화면 → 신호 선택 그래프.

### 1번 질량·무게중심 도구 사양 (2026-11-01 확정)

- 부품 질량 표: 범주 4개(현가상 / 현가상 · 드라이버 / 현가하 앞 / 현가하 뒤) 안에 묶음과 항목을 자유롭게 추가. 표를 채우면 총질량 · 앞뒤 · 좌우 배분 · CG 높이 · 현가상질량과 그 CG 높이 · 현가하질량(앞·뒤)이 계산된다. 차량 CG는 전체 질량(현가상 + 현가하)으로, 현가상 CG는 롤 계산용으로 따로.
- 드라이버 모델 편집 화면: 측면 드라이버 자세 그림(시트·페달·핸들 포함). 입력 = 엉덩이점, 등받이 각, 페달 · 핸들 위치, 키, 몸무게, 체절 길이(키 비율로 초기값, 하나씩 수정 가능). 다리 · 팔 관절 각은 엉덩이점-페달, 어깨-핸들 사이에서 자동으로 맞춤. 체절 질량 · CG 위치는 체절 비율 표(de Leva 1996). 1st · 2nd · 3rd 드라이버를 따로 저장하고 질량 표에서 고른다. 실측 CG가 있으면 그 값이 우선.

### 도구 사이 입력 관계

- 1번은 2·3·6·7번의 공통 입력이다.
- 4번 엔진은 5·6·7번의 공통 바탕이다. 5번을 먼저 만들면 엔진을 다시 나눠야 할 수 있다.
- 4·5번은 1~3번 없이도 만들 수 있다. 다만 5번에서 슬립을 반영하려면 질량과 무게중심이 필요하다.

### 5번 조향 도구 사양 (이전 논의에서 확정)

- 3D 킹핀축 전체와 서스 트래블을 함께 계산한다(범프 스티어, 롤 스티어).
- 타이어 모델 선택: 없음(기본) / 선형 가정값 / TTC(자리만). 슬립을 계산하려면 설계 코너 입력이 필요하다.
- 3D 입력을 "모름/고려 안 함"으로 두면 2D 계산으로 줄어든다.
- 목표는 부분 애커먼이다. 비율 지표는 작은 조향각에서 발산하므로 다른 지표를 함께 쓴다.
