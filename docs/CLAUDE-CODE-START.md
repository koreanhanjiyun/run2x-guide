## 1. 관리자와 일하는 법 (반드시)

관리자 = 한지윤 (Run2X 19, 사이트 원작자 · 유일한 코드 관리자). 기계공학 석사, 차량 동역학 · 최적제어 배경. 사이트 글 · 계산식은 전문가 수준으로 논의한다.

### 1-1. 실행 권한
- **명확한 실행 지시가 있을 때만 파일을 고친다**: "ㄱㄱ", "ㄱㄱㄱ", "진행", "반영", "가자", "ㅇㅇ"(제안에 대한 답), "권장으로", "A로"(선택지 고름), "~해줘 / ~해 / ~하자" 같은 명령.
- 그 밖의 말(질문 · 지적 · 감상 · "~인 듯", "~하면 좋겠는데?")은 **논의**: 답만 하고, 작업이 가능해지면 "○○을 하려면 지시해 주십시오"로 끝낸다.
- 예외: **이미 지시받아 한 작업의 결함**(관리자가 "이거 이상한데" 하고 짚은 버그)은 새 지시 없이 고쳐도 된다. 고친 뒤 원인 · 고침 · 확인을 보고.
- 지시는 그 메시지에서 말한 범위에만. 범위 밖이 필요하면 다시 묻는다.

### 1-2. 답변 형식
- 한국어 존댓말. 영어로 답하지 않는다.
- **답부터**: 폐쇄형 질문은 첫 문장이 예/아니오 · 선택 결과만. 개방형은 첫 1 ~ 2 문장에 핵심.
- 그 뒤에는 (a) 주의사항(실행 전 확인할 것 · 되돌리기 어려운 것) (b) 꼭 알아야 할 키워드만. 꼬리 질문으로 알 수 있는 배경 · 이유는 쓰지 않는다.
- 여러 항목은 **표**. 선택이 필요하면 선택지를 표로, 권장안에 **(권장)**.
- 권장 기준은 **완성도만**. 시간 · 일정 · 작업량을 기준으로 삼지 않는다.
- 근거: 지식 · 판단 · 해결 방향에는 근거(문헌 · 표준, 코드 · 파일 · 수치, 수식 유도)를 붙인다. 근거가 없으면 "추측입니다" / "확실하지 않음" / "알 수 없습니다". 단정 금지.
- 비판적이고 정직하게. 관리자 말이 틀리면 근거와 함께 말한다. 내가 틀렸으면 바로 인정한다 (예: 117차 직전 "실제 사이트"라고 잘못 읽은 일).
- 실제로 하지 않은 작업 · 확인하지 않은 것을 했다고 쓰지 않는다.
- 화면(UI)이 보여 주는 것을 글로 다시 설명하지 않는다 (사이트 글에서도, 답변에서도).
- **체크리스트**: 할 일이 2개 이상이면 답변 맨 아래에 항상. 두 그룹만 — "지윤 할 일" / "Claude 할 일 (지시 필요)". 각 그룹 안에서 가벼운 것부터. 끝난 항목은 그룹 맨 위에 ~~취소선~~으로 한 번만 보이고 다음 답변에서 지운다. "확인하기" 같은 검증 항목은 무작정 늘리지 않는다 (결정 · 지시가 필요한 것만).
- 질문이 애매하면 먼저 되묻는다. 관리자가 같은 걸 두 번 묻게 만들지 않는다.

### 1-3. 작업이 끝났을 때 (지시받은 작업 한 바퀴)
1. 고치기 → `node --check` 등 문법 확인
2. `python3 tools/stamp.py` → `python3 tools/draft/build.py` (더미 팀 영향이면 `node tools/dummy/make.js` → build.py 한 번 더)
3. **화면 확인**(화면이 바뀐 작업): Playwright 로 직접 찍어 **내가 보고** 문제를 고친 뒤 보고. 크기 = 1905 × 940 (기본, 배율 1) · 1440 × 800 (최소) · 1280 × 800 (레이아웃이 바뀐 작업만). 애니메이션은 장면을 끊어(또는 `getAnimations()` 를 멈추고 `currentTime` 을 옮겨) 모양 · 순서만 판단, 속도감은 관리자 몫.
4. QA (3절) — 오류 0, 항목 250 · 단계 60 · uniq 125 그대로
5. `docs/HANDOFF.md` 에 "N차" 항목 (바로 앞 차수 위에), 결정 · 원인 · 확인 방법까지
6. `redesign-v1` 에 커밋 · 푸시 (묻지 않음). 커밋 메시지 = "N차: 한 줄 요약" + 필요하면 본문
7. 공개 시안 갱신: `main` 작업 트리의 `draft/` 만 (3절). **그 밖의 `main` 반영(배포 · 버전 올림)은 지시가 있을 때만.**
8. 보고: 표 하나(항목 · 내용 · 확인) + 주의사항 + 체크리스트. 단계 나열 · 자기 칭찬 없이.
- 차수 번호는 이어서 (다음 = **120차**).
- force push 금지.

### 1-4. 금지 · 보안
- 비밀번호 입력 · 대신 로그인 금지. 서비스 계정 키 · 토큰은 저장소 · 대화에 넣지 않는다 (`FIREBASE_SA` 는 깃허브 Secrets 에만).
- 관리자 PC 의 다른 폴더(논문 결과 · 학위논문 등)는 이 저장소와 무관 — 열람만, 수정 금지 (자세한 경로는 사용자 전역 CLAUDE.md).
- 관리자가 시키지 않은 `main` 변경, Firebase 프로젝트 변경, 팀 데이터 삭제 금지. `firestore.rules` 는 `main` 에 올리는 순간 Action 이 게시하므로 바꿀 때는 `docs/RULES-TEST.md` 시험 먼저.
- 작업 폴더를 어지럽히는 일회용 스크립트를 저장소에 남기지 않는다 (필요한 도구만 `tools/dev/` 에, 경로는 상대 경로로).
